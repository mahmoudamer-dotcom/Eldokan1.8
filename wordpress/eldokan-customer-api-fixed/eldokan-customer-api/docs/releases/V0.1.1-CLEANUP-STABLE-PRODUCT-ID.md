# ElDokan Customer API 0.1.1 — Cleanup & Stable Product ID

## Why this release exists

Live testing of 0.1.0 proved that catalog, categories and product detail can read real WooCommerce data successfully.

Testing also exposed two integration issues:

1. WordPress canonical/rewrite behavior can redirect a product slug path to the public product page.
2. Raw WordPress/WooCommerce presentation details such as HTML entities and editor metadata were leaking into the API response.

## Main decision

Product detail now uses the ElDokan public product ID as the canonical API lookup:

```text
GET /products/prd_21417
```

Slug lookup remains available explicitly:

```text
GET /products/by-slug/{slug}
```

## Cleanup

- `&amp;` becomes `&` in display text.
- `&nbsp;` is removed from formatted price strings.
- WooCommerce `instock` becomes ElDokan `in_stock`.
- WooCommerce `outofstock` becomes ElDokan `out_of_stock`.
- WooCommerce `onbackorder` becomes ElDokan `on_backorder`.
- WordPress shortcodes are stripped from public HTML.
- Editor `data-*` metadata is removed from public HTML.
