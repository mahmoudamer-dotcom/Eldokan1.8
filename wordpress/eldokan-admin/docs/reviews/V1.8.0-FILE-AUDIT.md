# ElDokan Admin 1.8.0 — File Audit

## Scope

This audit covers the production plugin package used as the base for version 1.8.0.
The goal of 1.8.0 is a presentation-layer redesign with tightly limited UI permission cleanup.

## Runtime Files

### `eldokan-admin.php`

- Reviewed plugin bootstrap and load order.
- Changed only the public plugin version and `ELDOKAN_ADMIN_VERSION` to `1.8.0`.
- Existing duplicate-version collision protection remains intact.
- Existing activation hooks and required runtime files remain intact.
- PHP syntax check: PASS.

### `includes/class-eldokan-admin.php`

- Reviewed the main controller and all registered hooks.
- Existing action/filter hook set is unchanged.
- Existing `eldokan_admin_*` action identifier set is unchanged.
- Existing custom capability token set is unchanged.
- Added the modern page header markup used by ElDokan Admin pages.
- Redesigned dashboard cards, quick navigation and charts.
- Dashboard links are filtered using existing view capabilities.
- Orders hide update/open controls from users without `eldokan_backoffice_manage_orders`.
- Registrations hide approve/reject/delete controls when the required existing capabilities are absent.
- Product edit controls are hidden from users without `eldokan_backoffice_manage_products`.
- Inline commission mutation forms are replaced by a read-only state when the current user lacks `eldokan_backoffice_manage_commissions`.
- Category attribute controls are hidden from users without `eldokan_backoffice_manage_categories`.
- Server-side handlers, nonces and authorization checks remain authoritative and were not removed.
- PHP syntax check: PASS.
