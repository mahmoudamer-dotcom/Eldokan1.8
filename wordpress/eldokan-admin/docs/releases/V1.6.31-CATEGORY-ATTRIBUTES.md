# ElDokan Admin 1.6.31 — إدارة خصائص الفئات

## التركيب والضبط
1. استخدم إضافة Dashboard API الأصلية 1.75.68؛ هذه الحزمة لا تحتوي تعديلًا لملفات الـAPI ولا تحتاج النسخة التجريبية 1.75.69.
2. استبدل نسخة ElDokan Admin 1.6.30 بهذه النسخة 1.6.31. حافظنا على اسم المجلد الداخلي كما وصل في الملف المرفق (1.6.29-SAFE-ORDER-WORKFLOW)، رغم أن الإصدار بداخله أصبح 1.6.31. حدّث الإضافة المثبتة نفسها ولا تفعّل نسخة ثانية بجوارها.
3. افتح ElDokan Admin → Categories → Attributes بجوار الفئة المطلوبة.
4. عند Women اختر «تحديد خصائص هذه الفئة»، وحدد مثلًا color وSize ثم حفظ.
5. اترك Home wear وLingerie في وضع التوريث. تظهر خصائص الأم حتى لو لم يُضف أي منتج إلى الفئتين.
6. لتخصيص فئة فرعية، حدد خصائصها بصورة مستقلة. اختياراتها تستبدل قائمة الأم بالكامل. اختيار «بدون خصائص» أو تحديد قائمة فارغة يعيد قائمة فارغة ولا يرجع لمنتجات قديمة.
7. حدّث واجهة التجار إلى الحزمة 1.75.74 وأعد تحميل صفحة إضافة المنتج.

## التوافق وحدود النطاق
- الربط عبر نفس المسار /eldokan/v1/product-attributes ونفس categoryId ونفس شكل الرد.
- تستخدم الإضافة rest_dispatch_request بعد اجتياز صلاحية المسار الأصلي. لا تُسجل مسارًا عامًا جديدًا، ولا تستبدل إعدادات تسجيل الدخول أو CORS أو الصلاحيات.
- بدون ربط صريح للفئة أو أحد آبائها، يُنفذ رد الـAPI القديم كما هو، بما فيه الاستنتاج من 300 منتج. اضبط الفئات الأساسية للحصول على خصائص مستقلة عن وجود المنتجات.
- تُقرأ نفس مفاتيح الإعدادات من النسخة التجريبية السابقة، لذا تُحفظ الروابط السابقة إن كانت قد أُنشئت. واجهة الإدارة أصبحت داخل ElDokan Admin.
- لا تُعدل خصائص المنتجات القديمة، ولا تضاف قيود جديدة إلى حفظ المنتج أو استيراده. نطاق التعديل هو إعداد قائمة الخصائص المتاحة في نموذج الإضافة.
- قيم السمات نفسها تأتي من مسار terms الأصلي؛ لا تغيير في معانيها أو طريقة حفظها.
- الفئات المترجمة ذات المعرفات المختلفة في WPML تحتاج ضبط شجرتها أيضًا؛ لم تتغير إعدادات اللغة أو الترجمة.

## الملفات المعدّلة فقط
- eldokan-admin.php: رقم الإصدار وتحميل وتهيئة مكوّن خصائص الفئات.
- includes/class-eldokan-admin.php: زر Attributes داخل جدول الفئات وفتح شاشة ضبط الخصائص فقط.
- includes/class-eldokan-category-attributes.php: ملف جديد لإدارة الربط والتوريث والرد على طلب الخصائص.
- هذا الملف: تعليمات الإصدار.
جميع الملفات الأصلية الأخرى مطابقة بايتًا ببايت للملف المرفق 1.6.30. لا تغيير في العمولات، الطلبات، التقارير، التجار، الأدوار أو أي إعداد آخر.

## التحقق
- نجح فحص PHP syntax لكل ملفات الإضافة الأربعة باستخدام PHP WASM CLI.
- نجح 30 تحققًا سلوكيًا في PHP مع بدائل اختبار لدوال WordPress/WooCommerce، وتحميل كلاس API الأصلي 1.75.68 فعليًا لفحص الرجوع للاستنتاج القديم.
- شملت الاختبارات: فئة فارغة، التوريث، أقرب أب، التخصيص، بدون خصائص، سمات محذوفة، سلامة حفظ IDs، رفض الصلاحية والـnonce، عدم تغيير بيانات رسوم الفئة، وعدم اعتراض مسارات أخرى.
- لم يُجرَ اختبار على قاعدة بيانات الموقع الفعلية أو خادم WordPress حي. جرّب فئة فارغة على نسخة تجريبية قبل تحديث الإنتاج.

مرجع ترتيب فحص الصلاحية والـhook: https://developer.wordpress.org/reference/classes/wp_rest_server/respond_to_request/
