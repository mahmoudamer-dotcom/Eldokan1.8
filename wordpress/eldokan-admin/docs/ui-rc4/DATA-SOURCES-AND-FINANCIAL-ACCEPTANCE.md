# مصادر الأرقام وقبول التقارير المالية

كل الأرقام المعروضة مصدرها الاستعلامات الأصلية؛ لم نضف analytics أو رصيدًا مصطنعًا. دوال الحساب المالي وREST overview متطابقة نصيًا مع RC3. التغيير الحالي في التسميات والتنبيه إلى حدود الملخص، لا في تعريف العملية المالية.

| الرقم / الشاشة | المصدر والتعريف الحقيقي | الحدود والقرار |
|---|---|---|
| تسجيلات معلقة | pending_registration_count من الحسابات ذات بيانات التسجيل وحالة pending | ليس عدد كل حساب بدور تاجر؛ يلزم مقارنة بيانات حقيقية |
| حسابات التجار | WP_User_Query للأدوار eldokan_owner/wcfm_vendor/vendor/seller | عد حسابات، وليس إثبات عدد كيانات تجارية فريدة |
| حسابات العملاء | customer/subscriber | لا يشمل زوار checkout، ولا يشترط عملية شراء؛ أزيل الرابط المكسور |
| المنتجات | wp_count_posts: publish+pending+draft، والانتظار pending | post records؛ قد تشمل ترجمات WPML؛ لا تمثل parent+variation بشكل تجاري موحد |
| طلبات مرتبطة بتاجر | overall_metrics: أحدث 300 طلب، ثم تاريخ 30d، وبند له item_seller_id | العينة تُقطع قبل تصفية المدة، فتفقد طلبات أقدم داخل الفترة؛ لا يعتمد كإجمالي |
| قيم البنود والوحدات | مجموع get_total/quantity في البنود المرتبطة بالتاجر بجميع الحالات | لا يخصم refund مثل التقرير المفصل؛ ليس إيرادًا محصلًا |
| العمولة التقديرية | commission_amount/current effective_rule في العينة | قواعد حالية قد تختلف عن snapshot التاريخي؛ لا تستخدم للصرف |
| إلغاءات الملخص وتقييم الأداء | cancelled/failed ضمن عينة 300؛ automatic_cancel_rating يبني عليها | لا يطابق تعريف rejected/returned في تقارير أخرى؛ يلزم تعريف عمل موحد لاحقًا |
| رسم حالات الطلب | أحدث 150 طلبًا، مجموعات processing/completed/pending/cancelled/refunded/other | ليس ملخص فترة ولا تحليلًا مستقلًا للحالات المخصصة |
| رسم Distribution | منتجات وحسابات وطلبات عينة في دائرة واحدة | وحدات وقواعد زمنية مختلفة؛ المقارنة بالنسب ليست مؤشرًا تجاريًا معتمدًا؛ يوصى استبدال الرسم لاحقًا |
| visits/unique في overview | مجاميع eldokan_admin_traffic حسب day، وcookie لتمييز الزائر | unique اليومي لا يساوي زائرًا فريدًا على الفترة؛ تتأثر بالكوكيز/الـcache؛ لم يختبر تتبع حي |
| التقرير المالي المفصل | seller_financial_report_rows عبر wc_get_orders بدفعات 200 حتى max_num_pages | يتجاوز حد 300؛ تاريخ إنشاء الطلب وليس تاريخ دفعه أو تسويته |
| مبيعات محققة | is_paid مع استبعاد cancelled/refunded/failed/rejected/returned، قيمة السطر+ضرائبه ناقص refund/ضرائبه | تحصيل معرف من Woo؛ ليست مصادقة بنك أو مزود دفع |
| عمولة التقرير | لقطة رسوم السطر أولًا ثم legacy/current؛ قاعدة قيمة السطر دون ضريبة بعد refund؛ clamp للمبيعات | fallback قد يعيد احتساب تاريخ قديم بالقواعد الحالية؛ يلزم تحديد provenance لكل بند |
| صافي التقرير | realized_sales − commission مع قيود عدم السالب | ليس رصيد سحب؛ لا يثبت احتساب شحن/ضريبة عمولة/رسوم بوابة/حجوزات/صرف سابق |
| فرق المطابقة | sales − commission − seller_net | هوية حسابية داخلية؛ صفرها لا يثبت مطابقة سجل دفع أو تسوية خارجية |
| النشاط الأخير | أحدث 5 صفوف من جدول تدقيق Admin عند وجوده وصلاحية view_activity | عرض مقيد وصافي escaping؛ ليس سجل أحداث كامل لكل مزود خارجي |

## نموذج مالي منفذ

320 طلبًا مصطنعًا، سطر واحد بقيمة 100 لكل طلب، عمولة snapshot مقدارها 10%، مع cancelled وpending وrefunded وpartial refund بقيمة 20. أعطى الملخص القصير 300 طلب وقيمة 30000 تشمل حالات غير مدفوعة. التقرير التفصيلي عالج 320 سطرًا وأعطى sales=31680، commission=3168، seller_net=28512، difference=0. جميعها وحدات fixture، وليست إيرادات المتجر. الدليل قابل لإعادة التنفيذ في admin-regression.php ونتيجته JSON.

## ما بقي للقبول المالي

مطابقة على snapshot حقيقي منزوع البيانات الحساسة حسب seller/item/order/currency: رسوم النسبة والثابت والهجين والسقف، قواعد القسم/المنتج/المالك وأولويتها، أدوار الموظفين، منتجات محذوفة ومترجمة وvariations، قسائم وشحن وضريبة، refund كلي وجزئي وتعدد refunds، الحالات المخصصة وCOD وPaymob، ودقة التقريب وحدود اليوم والتوقيت. يجب تفسير كل فرق قبل استخدام التقرير للتسوية.

توجد نصوص EGP موروثة في بعض البطاقات، فيما wc_price يتبع إعداد المتجر في مواضع أخرى؛ دعم عملات متعددة غير معتمد. حدود التاريخ تستخدم مسارات timezone مختلفة في الملخص والتقرير؛ لم نعد كتابتها. واجهات Woo في إدارة الطلبات لا تمنح تلقائيًا شهادة HPOS للـSQL الموروث للفهرسة أو لكل الملحقات.

**القرار: تقارير تشغيلية تحتاج قبولًا ماليًا مستقلًا؛ لا تصريح للصرف أو ترحيل أرصدة أو تعطيل WCFM.**
