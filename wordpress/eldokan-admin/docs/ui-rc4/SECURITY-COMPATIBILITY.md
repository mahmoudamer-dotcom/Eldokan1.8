# ملاحظات الأمان والتوافق

حد التنفيذ: Admin Staff فقط. لم تتغير REST namespaces/routes/response shapes أو storage keys أو tables أو cron أو سلوك Woo/Paymob أو ملكية التاجر أو employee capabilities. Customer/Seller API وClient/Frontend لم تُعدّل. لا نشر أو كتابة بيانات حية أو تعطيل WCFM.

- النماذج تحتفظ بـaction/method/field names/nonces والاختيارات والقيود الأصلية؛ نموذج DOM قارنها قبل/بعد. جميع admin-post/AJAX الموجودة في نموذج التسجيل اختُبرت ضد مستخدم غير مصرح قبل الكتابة، مع اختبار nonce سيئ ومسارات حفظ مختارة. هذا لا يثبت كل مسار ناجح داخل WordPress.
- إصلاح التنقل يسجل alias من نوع admin_page إلى callback hook الموجود أصلًا، بصلاحية ذلك المسار نفسها قبل dispatch. لا إزالة للخطاف الأصلي ولا منح صلاحية. اختبار سحب الصلاحية بعد التسجيل يمنع dispatch، والـrenderer يطبق الحماية الأصلية أيضًا. أضيف فحص manage_options داخل Dashboard Control مطابقًا لتسجيل الصفحة.
- أدوات الجدول والطي والتأكيد تحسن العرض فقط؛ لا تعديل للأذونات أو إرسال شبكة أو إعادة محاولة mutation. إلغاء الحوار يستعيد التركيز؛ التأكيد على العميل لا يحل محل حماية الخادم.
- النشاط الأخير محصور بصلاحية view_activity ويقرأ خمس سجلات فقط ويهرب النصوص. رسائل WCFM الديناميكية أصبحت مترجمة ومهربة؛ قيمة ready ومعالج التحقق لم يتغيرا. لا تُعرض secrets أو بيانات جلسة من API في التقارير.
- CSS معزول بعلامة الشاشة، والأصول تحمل allowlist خاصًا بهذه الإضافة وشاشات Story. فُحصت المحددات بنيويًا ونموذج شاشة غير تابعة؛ لا ادعاء شهادة collision مع كل Plugin حي.
- لا مكتبة تشغيل أو CDN جديد. اعتماد Chart.js الخارجي الموجود سابقًا باقٍ على dashboard فقط؛ انقطاعه لا يجعل بيانات الاختبار دليلًا على عمل الرسم. أدوات الاختبار لا تدخل حزمة التثبيت.
- Eight operational files مطابقة بايتًا لـRC3، بما فيها Checkout وStories وroles وHome. hooks والـcron والتكاملات التشغيلية تبقى؛ أضيفت filters عرض/تسجيل aliases فقط. لا إضافة مستقلة للـCheckout أو Stories.
- WC order APIs محفوظة، وWPML وعلاقات الوسائط وترتيب/جدولة/ترجمة Stories محفوظة في دوالها. هذه مقارنة مصدر واختبارات نماذج، وليست قبول HPOS/WPML/وسائط/Webhook فعليًا.
- schema ensure والترحيلات الأصلية قد تعمل على قاعدة ناقصة كما قبل؛ لم نضف أو نشغّل migration. الرجوع بالملفات لا يلغي عملية بيانات نفذها مشغّل بعد التثبيت.

قبل الإنتاج يلزم تنفيذ STAGING-ACCEPTANCE-AND-ROLLBACK.md وتسوية عيوب الملكية والقبول المالي في checkpoints مصرح بها. لا يمكن اعتبار WooCommerce وحده بديلًا تلقائيًا لوظائف multivendor أو للصرف والشحن من WCFM.
