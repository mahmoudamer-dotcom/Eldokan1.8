# v0.2.0 — Catalog Contract Hardening

**Date:** 2026-09-21  
**Contract namespace:** `eldokan-customer/v1`  
**Scope:** read-only catalog

## Delivered

- Typed catalog contract and endpoint-specific OpenAPI responses.
- Real category attribute filtering on the server.
- ElDokan-owned attribute/variation representation.
- Explicit seller ownership and consistent public visibility.
- Variable price ranges and variation purchasability.
- Effective cache keys plus retained diagnostics and broader invalidation.
- Arabic route support, localized Home labels and WPML-aware lookup/filter scoping.
- Standard namespace errors and smaller Home payload.
- Updated documentation, tests and Developer Portal 1.3.0.

## Compatibility

All v0.1.4 endpoints remain. Existing public ID formats remain. Product pricing gains `min_price` and `max_price`. Variation `attributes` changes from undocumented Woo maps to the documented selection array; this is a required contract correction before production frontend adoption. Seller values may become `null` for legacy or unsafe ownership records.

## Required live acceptance

PHP lint and staging/live WordPress tests remain mandatory. See `docs/TESTING.md`, especially seller migration, WPML/Arabic, visibility, variations, filters, cache and standard errors.
