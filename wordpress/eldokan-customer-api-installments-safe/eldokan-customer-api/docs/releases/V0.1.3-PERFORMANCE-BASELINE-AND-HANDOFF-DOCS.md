# ElDokan Customer API 0.1.3
## Performance Baseline & Handoff Documentation

### Goal

Make performance and maintainability first-class requirements before the frontend starts depending heavily on the API.

### Runtime changes

- short-lived public catalog cache;
- cache HIT/MISS/BYPASS diagnostics;
- server-side processing timing header;
- cache generation invalidation;
- reduced `/home` initial product load.

### Why not simply increase server resources?

The architecture must remain portable across hosting providers.

The first response to slow endpoints is:

```text
measure
bound queries
remove full scans
cache safe read models
reduce payload
optimize indexes/query strategy
```

not permanent dependence on one hosting provider.
