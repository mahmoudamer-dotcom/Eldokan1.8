# v0.2.2 — Product Detail Consistency

## Scope

This patch changes only ProductDetail image consistency and current documentation/version metadata. Filtering, caching, translation, seller logic, routes, IDs and all other runtime behavior remain unchanged.

## Fixed

- ProductDetail runtime now returns `image`, matching the already-required OpenAPI field.
- `image` is the primary product image or `null`.
- `images` remains the ordered full collection: primary image first when available, followed by gallery images.
- The Customer API verifier now checks that both fields remain in `serialize_detail()`.
- Arabic study notes now document `_eldokan_seller_user_id` as the only seller ownership source and reject legacy fallbacks.
- Testing documentation now separates Customer API source checks from Developer Portal/OpenAPI checks.

## Verification boundary

All nine PHP files in 0.2.1 were independently reported to pass `php -l`. Because this release changes `class-eldokan-customer-api-products.php`, lint the 0.2.2 package again. Live WordPress testing must verify a product with a primary image/gallery and a product without a primary image.
