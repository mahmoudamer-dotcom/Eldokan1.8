# ElDokan Customer API 0.1.2
## Catalog Consistency & Category Filters

### Why this release exists

Live tests proved:
- health works,
- category listing works,
- product listing works,
- stable product-ID detail works,
- search suggestions work,
- home data works.

The tests also exposed:
1. WordPress canonical redirects for a path ending in a real product slug.
2. `smartphones` returned `unconfigured` even though the existing ElDokan system intentionally falls back to discovering attributes from products.
3. Home/catalog data could expose standalone variation child objects.
4. Product HTML could still contain Unicode non-breaking spaces.

### Product lookup

Primary product reference remains:

```text
GET /products/prd_21417
```

Secondary slug lookup becomes:

```text
GET /products/lookup?slug=product-slug
```

### Category attribute rule semantics

The Customer API now mirrors the existing ElDokan Admin behavior:

```text
custom rule
    ↓
use configured attributes

none rule
    ↓
return no attributes

inherit/unset
    ↓
check nearest parent

no explicit rule anywhere
    ↓
discover attributes from products
```

### Customer filter options

The API only returns attribute terms actually represented by published parent products in the requested category or its descendants.

This is intentionally different from the Seller product-entry use case, where all possible taxonomy terms may be useful.

### Performance

Attribute discovery is done from WordPress taxonomy relationships rather than loading hundreds of WooCommerce product objects.
