# Customer API 0.5.0 — Phase 2A

This additive Contract v1 release adds customer Identity/Auth, Account and Wishlist only.

## Session mechanism

The adapter uses WordPress-native authentication sessions. The logged-in cookie is HttpOnly and is reissued with Secure on HTTPS and SameSite=Lax. Register, login and session restoration return a session-bound CSRF value; every authenticated mutation requires it through `X-ElDokan-CSRF`. No JWT, refresh token or long-lived localStorage credential is introduced.

Credentialed CORS is restricted to the WordPress site origins and explicitly configured frontend origins. Future `api.eldokan.com` migration must configure the frontend origin/cookie domain at deployment time without changing components or the Client surface.

## Available

- `POST /auth/register`, `POST /auth/login`, `GET /auth/session`, `POST /auth/logout`
- `GET /me`, names-only `PATCH /me`
- `GET /wishlist`, `POST /wishlist/items`, `DELETE /wishlist/items/{product_id}`

Wishlist additions validate the accepted `prd_*` parent ID through the existing public visibility rules. Duplicate add and missing remove are deterministic and return `changed:false`.

## Not available

Authenticated Seller Account remains Seller Portal/Seller API. Cart/Guest Session, Checkout, Orders, Product Review submission and Seller Rating submission remain outside Phase 2A.
